# targets: @target keys, entry parameters and libraries, use, the manifest palette p

An entry file may declare `param name:default` controls. `--set` binds those controls for selected targets without replacing matrix axes or arbitrary `let` bindings. Imported entries use private defaults. See `values`.

`preview --target PATH` selects the exact expanded output path relative to the manifest output directory. A path such as `hero/red@2x.png` identifies its matrix cell and scale. An ambiguous file requires this selector. Preview preserves that output's canvas, palette, background, matrix, and evaluation scale. Crops and presentation backgrounds operate on the resulting pixels. See `cli`.

- An **entry file** starts with one or more `@target` lines. Any file without one is a **library** and may only hold `use`, `palette`, `style`, `finish`, `def`, `rule`, `let`, `anim`.
- `@target produce/peach.png 1024x1024 scale:1,2` writes `peach.png` and `peach@2x.png`. The size is the canvas in canvas units, before `scale:`. Each PNG is the canvas times its scale, rounded up to whole pixels, so `32x20` at `scale:2` is 64x40 pixels. `.svg` targets write SVG. `.gif` targets write one GIF for each scale, named and sized like a PNG, so `walk.gif` with `scale:1,2` writes `walk.gif` and `walk@2x.gif`. Keys: `bg:none|<color>`, `as:<label>` (the file reads it as `target`), `scale:` (the file reads the scale of the output it draws as `scale`: a `.png` or `.gif` output's own number, and 1 in a `.svg`, so a def can keep a constant pixel width with `stroke:ink,1/scale`; a def parameter, `let`, or global named `scale` wins, and the file is evaluated and checked once for each scale), `profile:vector|svg|raster|auto` (`vector` and `svg` need an `.svg` target, and an unknown word is an error), `fps:` (default 24), `dur:`, `clip:` (the file reads it as `clip`, default `none`), `t:` (the time a still draws, default 0), `pivot:` (a point in canvas units, `pivot:48,96`, `pivot:50%,100%`, or an anchor such as `pivot:@leg.hip`; a node is E0206, and so is `pivot:` on a `.gif`), `palette:<palette>` (a palette or a `use … as` palette module that `p` names for everything the target draws; any other value is E0206), a bare `viewport` marks the canvas as a crop of a larger scene and turns off the `off-canvas` lint for that target, `each k:[a b]` fans out a matrix interpolated as `{k}` in the path. A path may also hold `{scale}`, the scale number (`0.5`, `2`), and `{w}` and `{h}`, that output's size in pixels, so `icon_{w}.png` with `scale:1,2` on `32x32` writes `icon_32.png` and `icon_64.png`. A `.png` or `.gif` path that holds any of them drops the `@Nx` suffix, and a path without one keeps it. A `.svg` path fills them with scale 1 and the canvas size. An axis named `w` or `h` is E0206, because it would clash with `{w}` and `{h}`. `fmt` prints `clip:` after `each`. `bg`, `scale`, `as`, `fps`, `dur`, `t`, `clip`, `profile`, `pivot`, and `palette` are never axes, so `clip:[idle blink]` stays a `clip:` error. An unknown key or bare word is an error. `target` is reserved, so `let target = 1` is an error. `target` holds the `as:` label as a word, or `none` when the target has no `as:`. It never holds the output path. The `unknown-target` lint (L0106) warns when the entry file compares `target` with `==` or `!=` to a word or string that no `@target` in that file can give it, and it names the labels. A name the file binds or imports is not checked, because its value is known only when the file runs. A library is not checked. A GIF needs an opaque `bg:`, at most one frame per centisecond of `dur`, and at most 256MiB of raster and 256MiB of retained frames.
- Each `.png` and `.svg` entry in `art-manifest.json` carries `pivot` (`null` without a `pivot:`) and `anchors`, the position of every anchor the file placed by the path an author writes after `@` (`body.neck`). Both are in that output's pixels, so `x@2x.png` holds twice the numbers of `x.png`. A `_` anchor inside a def is left out. A `.gif` entry carries neither, because its anchors move per frame.
- `use face/eye` imports a library from the manifest's lib roots. `use palette/dusk as p` aliases it. `use face/parts { eye blush }` imports names. Names starting with `_` stay private. `use std/brushes { dry chip }` imports a bundled library: `std/` resolves only against the libraries built into `ramose`, a project file under `std/` at the project root or at a lib root, which `use std/...` would otherwise reach, is E0213, and `ramose std` lists and prints them.
- `use art/tiles/rock` imports a file by its path from the project root, when no lib root has that path. The file can be an entry file. The importer gets its declarations, as from a library, and skips its `@target` lines, its top-level `let` lines, and its drawing. A def from that file that reads one of those skipped `let` names is E0201. So one entry file can write its own output and also give its defs to scenes. An entry file under a lib root is still E0203.
- A node that uses a raster-only feature, such as a field fill, a one-sided, masked, or brushed outline, a brushed fill or stroke, or a `warp:`, is baked to a PNG tile under `profile:svg` and reported as E0209 under `profile:vector`. A node whose brush reads `m.below` cannot bake, since a tile has no backdrop, and is E0209 under both profiles with the feature `brush below`.
- The `unused` lint reports an imported name the importing file never reads. `palette elite from house` reads `house`. A library's top-level `let` is an export, like a `def`, so the lint does not report it. A private `_` let is not an export, and the lint reports it when nothing reads it.
- A `use` that fails (the library does not parse, is missing, or lacks a listed name) is reported once, at its cause. Its names stay quiet where they are used, and after a bare `use x` so does any unknown verb, style, effect, or anim. A broken manifest palette does the same for `p`.
- The manifest's default palette is available as `p` in every file. See `manifest`. A `palette:` key on a `@target` or on a def instance rebinds `p` for everything drawn under it, library defs included. An inner `palette:` replaces an outer one. A file that binds `p` itself, with `palette p`, `let p`, or `use … as p`, keeps its own. A library's top-level `let` is evaluated once when the library loads, so `let tint = p.blue.2` keeps the manifest color under `palette:`. Read `p` in the def body or in a parameter default to follow the key. The `unused` lint counts `palette:elite` as reading `elite`.
