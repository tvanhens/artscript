# components: def, size box, slots, patches, let/if/each, style

```
def eye size:10 iris:p.sky.3 look:0,0
  circle size fill:#fff name:white
    circle size*.55 at:look*size*.3 fill:iris
  anchor brow 0,-size
  slot lashes at:0,-size*.8
```

- Positional arguments fill the parameters in order (`eye 9 at:-14,0`), so `def d a:1 b:2` called as `d 5 6` sets `a` to 5 and `b` to 6. Types come from the defaults. An instance also takes the node keys, `seed:n` pins every seed inside it, and `palette:elite` rebinds `p` for everything drawn under it, slot content and parameter defaults included. A `palette:` that is not a palette is E0320. A palette is not a parameter value either, so passing `elite` to a module parameter is E0320 and the fix names `palette:`.
- `kind:one_of(floor_top fill fill_b)` declares the words a parameter may take. The first word is the default. A call that passes any other word, or anything that is not a word, is E0320 at the call, and the message lists the allowed words. Positional, named, and alias-fixed arguments are all checked. In the def, comparing `kind` with `==` or `!=` to a word outside the list warns with the `unknown-word` lint (L0107), unless the body rebinds `kind` or the word is a name the body binds or another parameter. A plain word default such as `kind:floor_top` takes any word. `one_of` is only a parameter default, and its arguments are bare words.
- `size` is the def's box, centered on the origin. `size:40` is a square. `size:72x32` is 72 wide and 32 tall. A bare percent uses the smaller side. Percents in the body measure that box, and a child with no `at:` stays at the origin.
- Components are values, so `outfit:tunic` can be placed as `outfit`, and `none` draws nothing. A def may reuse a shape word. `def circle` is that component, not the built-in circle.
- `def arm_l = hero_arm tone:-1` declares an alias: `hero_arm` with `tone` fixed. An instance of `arm_l` is an instance of `hero_arm`, so it has `hero_arm`'s anchors, parts, and slots directly. `@arm_near.hand`, `.hand fill:p.red`, and `glove:` work as on a `hero_arm` instance, and `arm_l` draws the same pixels as `hero_arm tone:-1` at the same place, seeds included. An unnamed `arm_l` counts as a `hero_arm` among its unnamed siblings, so its path is `hero_arm~1`. A call fills the parameters the alias leaves open, positionals in the def's order, and may still pass `seed:`, `palette:`, and the node keys. Passing a key the alias fixed is E0321. An alias may fix any key a call takes except `name:`, which belongs on the instance, and a key the def does not declare is E0321 at the alias line. A fixed argument is evaluated like a parameter default: in the alias's module, with the instance's palette as `p`, so `palette:elite` on the instance recolors a fixed `tone:p.skin.3`. An alias has no body. It may alias another alias or an imported def, and it may be written above the def it names. A library `let` sees an alias declared above it, as it sees a def. An alias of itself, or of a name that is not a def, is E0323.
- `slot name` exposes an insertion point, filled by the caller with a `name:` block. A def body may hold `fx`, which attach to every instance and run before the call site's. A mask, a slot fill, or a patch cannot sit directly in a def body. Slot content is its own scope. `@part` there searches the content, then the host, then the caller. A def body sees only its own names. `needs:@torso` imports the host's `torso`, and a missing host or a missing part is an error at the call.
- `.arm_r rot:-20`, `.cape off`, and `.head.eye_l iris:p.accent` override a declared name from the instance block, in source order, with the last one winning. Every segment before the last is an instance or a slot, so `.head.eye_l` needs `head` to be one. `.eye.0` reaches one copy of a family, and `.eye.1 off` hides that copy. A segment may be a keyword when the part is a slot of that name, as in `.mask off`. Hiding the instance with `off` still checks a hop through it.
- A part whose name starts with `_`, as in `name:_core`, is private to its def. `@_core` works in the def body. A patch or an anim path from outside the def that names `_core` is an error, and `.*` skips it. `.*` also skips anchors, which have no node to change. The entry file has no caller, so its own `_` names stay patchable.
- `let w = if build == slim then 34 else 42`, `if`/`else` (a statement `if` takes a block, not `then`), and `each x in [..]` / `each i in 0..8` are bounded control flow. `each i in 0..8` runs 8 times, with `i` from 0 through 7. `each i, x in list` also binds the position `i`, from 0 in iteration order, with the index first, over a list or a range. `[each k in 0..n -> expr]` builds the list, and `[each i, x in list -> expr]` binds the position there too. A loop index does not change the seeds inside the loop.
- A parameter may hold a brush: `def stone tone:p.stone.3 brush:chip` and `rect size fill:tone brush:brush` in the body, or `brush:brush(scale:.5)` to re-call it with overrides. `brush` is a legal parameter name. An instance passes it like any parameter (`stone brush:dry`, `stone brush:none`); `brush:` on an instance whose def has no such parameter is E0321. A parameter whose default is a brush is brush-typed: an instance passes a brush or `none`, and a call on it checks its arguments against the default's declaration, so a bad key is E0361 for every instance. When the instance passed `none`, the call is `none`, so the body stays valid under `brush:none`. Calling a `none` parameter whose default is not a brush is an unknown function. A parameter may hold a stamp the same way: `def vine stamp:dots` with `curve 0,0 100,0 stamp:stamp(spacing:10)` in the body, an instance passes a stamp or `none`, and a call on the parameter is checked against the default (E0366). A def body also inherits the paint keys of the layer or style the instance sits in, `brush:` and `stamp:` included, so a shape in the body with no `brush:` of its own takes the layer's.
- `style ink stroke:p.ink,2` with `style:ink` applies those keys to a node and its descendants. A style takes keys only, never a block. A style holds keys that children inherit, while a finish holds effects that one node gets.
